= Observabilidad MaaS

Dashboards de uso y métricas del gateway según la https://rh-aiservices-bu.github.io/rhoai-maas-guide/modules/main/07-observability.html[guía MaaS Phase 7].

En RHOAI 3.5 el stack de dashboards usa *Cluster Observability Operator* (Perses) + Tempo + OpenTelemetry. Para usage por request: Loki + MinIO (lab) + `usageLogging`.

Hazlo *después* de xref:10-00-verify.adoc[probar inferencia] (o en paralelo si el modelo ya está Ready).

== Qué instala

[cols="2,3"]
|===
| Pieza | Para qué

| Tempo Operator
| Trazas; el Monitoring de RHOAI lo requiere

| OpenTelemetry Operator
| Collector CRD; sin él falla el cascade de observabilidad

| Cluster Observability Operator (COO)
| Perses + pestaña *Observe & monitor* en el dashboard RHOAI

| DSCI `monitoring`
| MonitoringStack, ThanosQuerier, datasources, dashboards

| `MaasTenantConfig.telemetry`
| Labels por modelo / subscription en métricas del gateway

| Loki + MinIO + `usageLogging`
| Dashboards de consumo (tokens) admin/user
|===

== Script (recomendado)

Desde la raíz del repo:

[source,bash]
----
bash manifests/apply-maas-observability.sh
----

Espera CSVs `Succeeded`, LokiStack Ready y el patch de `usageLogging`. En un OpenTLC de 1 nodo puede tardar *10–20 min*.

El script enciende *user-workload monitoring* primero (`enableUserWorkload: true`, pre-requisito de xref:03-00-monitoring.adoc[Prerrequisitos → Monitoreo]): sin él, RHOAI y Kueue no publican métricas y *Usage* se queda sin datos.

Si el script se corta en un `oc wait` (`no matching resources found`), vuelve a lanzarlo: es idempotente y el wait ahora espera a que aparezca el CSV.

=== 4. DSCI monitoring

Sin esto, la pestaña de dashboards no tiene datasource:

[source,bash]
----
oc patch dsci default-dsci --type=merge -p '{
  "spec": {
    "monitoring": {
      "namespace": "redhat-ods-monitoring",
      "metrics": {
        "replicas": 1,
        "storage": { "size": "5Gi", "retention": "90d" }
      },
      "traces": {
        "sampleRatio": "0.1",
        "storage": { "backend": "pv", "retention": "2160h" }
      }
    }
  }
}'
oc wait --for=jsonpath='{.status.phase}'=Ready dsci/default-dsci --timeout=300s
----

=== 5. Telemetría del gateway

[source,bash]

== UI — dashboards

. Dashboard OpenShift AI → *Observe & monitor* → *Dashboard*
. Abre *Usage* (tokens / requests / rate limits por subscription) y los dashboards MaaS
. Genera tráfico con el Playground o el `curl` del módulo 10; espera unos minutos

NOTE: El panel *Usage* es *Technology Preview* en RHOAI 3.5. Sirve para *showback* y atribución de consumo (export CSV).
*No* es un motor de billing con precio en dólares por token: eso no está en la subscription ni en el dashboard GA.
Para coste operativo en el lab usa rate limits (módulo 9) + Usage/Loki.

IMPORTANT: *GPU utilization* = *No data* es normal en este lab. El modelo del serving corre con imagen **vLLM CPU** (`rhaii/vllm-cpu-rhel9`) y **sin** `nvidia.com/gpu` en el `LLMInferenceService`. Fake/NVIDIA GPU (módulo 5) y DCGM están para perfiles/hardware; no alimentan el panel de GPU de este serving. Mira tokens, latencia y logs de usage en su lugar.

Si desplegaras el mismo modelo con imagen CUDA + request de GPU (real o fake), ahí sí aparecerían series DCGM.

=== Token consumption = 0 (Usage)

El panel *Usage → Token consumption* consulta Prometheus con filtro `user!=""`. Sin la label `user` en `TelemetryPolicy`, la UI muestra 0 aunque Limitador cuente tokens.

Fuerza la label (CPU o GPU; es del gateway, no del runtime):

[source,bash]
----
bash manifests/fix-maas-usage-user-label.sh
----

Luego genera tráfico (Playground o `curl` del módulo 10), espera ~1 min y refresca *Usage*. Deberías ver tokens con `user=admin` (o el username de la API key).

Verificación directa:

[source,bash]
----
oc port-forward -n redhat-ods-monitoring \
  svc/thanos-querier-data-science-thanos-querier 10902:10902 &
sleep 2
curl -sg --data-urlencode \
  'query=sum by (user,subscription,model) (increase(authorized_hits_total{user!=""}[30m]))' \
  'http://127.0.0.1:10902/api/v1/query' | jq
----

NOTE: Si `maas-controller` reconciliara el `TelemetryPolicy`, vuelve a ejecutar el script.

== FinOps rápido (rate limit)

Tras varias inferencias, HTTP `429` confirma Limitador. Los dashboards de usage muestran tokens por modelo/subscription cuando Loki está Ready.

[source,bash]
----
CLUSTER_DOMAIN=$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')
MAAS_URL="maas.${CLUSTER_DOMAIN}"
# Reutiliza API_KEY y MODEL_ID del módulo 10
for i in $(seq 1 20); do
  CODE=$(curl -sk -o /dev/null -w '%{http_code}' \
    "https://${MAAS_URL}/v1/chat/completions" \
    -H "Authorization: Bearer ${API_KEY}" \
    -H "Content-Type: application/json" \
    -d '{"model":"'"${MODEL_ID}"'","messages":[{"role":"user","content":"/no_think ping"}],"max_tokens":200}')
  echo "request $i -> HTTP $CODE"
  [ "$CODE" = "429" ] && break
done
----
