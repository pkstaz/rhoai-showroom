= Postgres, Gateway y modelsAsAService

Orden:

. Postgres + secret `maas-db-config`
. Gateway `maas-default-gateway`
. `aigateway.modelsAsAService: Managed` en el DSC

== Todo en uno

Un script resuelve el módulo completo en orden: operadores pre-requisito si faltan (Connectivity Link y Leader Worker Set), GatewayClass + Istio, Kuadrant, Postgres, Gateway y `modelsAsAService: Managed` en el DSC. Es idempotente: se puede re-ejecutar.

[source,bash]
----
bash manifests/apply-maas.sh
----

Con el operador ya instalado (xref:04-01-operators-maas.adoc[Prerrequisitos → Operadores MaaS]):

[source,bash]
----
bash manifests/apply-maas.sh --skip-operator
----

=== Desde otros proyectos

Clona este repo y ejecuta el script contra el cluster donde ya hiciste `oc login`:

[source,bash]
----
git clone git@github.com:pkstaz/rhoai-showroom.git
bash rhoai-showroom/manifests/apply-maas.sh --skip-operator
----

=== GitOps

La parte declarativa está lista para GitOps como bundle kustomize (GatewayClass, Kuadrant y Postgres):

[source,bash]
----
oc apply -k manifests/maas
----

El Gateway y el patch del DSC dependen de valores del cluster (dominio, certificado, nombre del DSC), por eso los maneja el script; en un repo GitOps pasarían a ser valores parametrizados (kustomize `replacements` o parches).

== 1. Base de datos

[source,bash]
----
oc apply -f manifests/maas/maas-postgres.yaml
oc get pods -n redhat-ai-gateway-infra
----

Espera el pod de Postgres `Running`. El YAML crea el Secret `maas-db-config`.

== 2. Gateway

[source,bash]
----
bash manifests/apply-maas-gateway.sh
oc get gateway maas-default-gateway -n openshift-ingress
----

`Programmed` = `True`.

== 3. Encender MaaS en el DSC

Hasta ahora `modelsAsAService` estaba en `Removed`. Aquí se deja el AI Gateway en `Managed` y se enciende MaaS en el `DataScienceCluster`:

[source]
----
aigateway:
  managementState: Managed
  modelsAsAService:
    managementState: Managed
----

=== Instalar por terminal

[source,bash]
----
oc patch dsc default-dsc --type merge -p '{
  "spec": {
    "components": {
      "aigateway": {
        "managementState": "Managed",
        "modelsAsAService": { "managementState": "Managed" }
      }
    }
  }
}'
----

== Verificar

[source,bash]
----
oc get dsc default-dsc
oc get pods -n redhat-ai-gateway-infra
oc get pods -n redhat-ods-applications | grep -i maas
oc get aitenant -A
oc get maastenantconfig -A
----

`maas-api` / `maas-controller` en `Running`.

== Auto-fix Authorino

Sin gRPC TLS alineado, la UI de *API Keys* y *AI Assets* fallan:

[source]
----
unknown error when invoking maas-api (unmarshall): invalid character 'I' looking for beginning of value
Models as a Service could not be loaded. Only models from available sources are shown.
----

Causa: Envoy habla TLS con Authorino `:50051` mientras el listener está en plaintext (y falta el service CA para validar `maas-api` HTTPS). El script `apply-maas.sh` lo detecta y corrige al final (re-ejecutándolo aplica los fixes de nuevo). Los fixes viven dentro del script (función `apply_authorino_fixes`).

Smoke test (respuesta JSON = transporte OK; sin subscription de xref:09-00-subscription.adoc[módulo 9] puede devolver error JSON, y es válido aquí):

[source,bash]
----
curl -sk -X POST "https://maas.$(oc get ingresses.config/cluster -o jsonpath='{.spec.domain}')/maas-api/v1/api-keys" \
  -H "Authorization: Bearer $(oc whoami -t)" \
  -H "Content-Type: application/json" \
  -d '{"name":"check","expiresIn":"1h"}'
----
