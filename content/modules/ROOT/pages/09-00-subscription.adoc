= Suscripción MaaS

Para consumir el modelo por el gateway hacen falta *subscription* y *authorization policy*.
Sin las dos, la `MaaSModelRef` no queda `Ready`.

Este lab usa el modelo in-cluster del módulo 8 (por defecto `qwen3-06b` CPU).
Si desplegaste GPU o TMM, aplica *también* su subscription.

== Qué se crea

[cols="1,2"]
|===
|Recurso |Detalle

|`MaaSSubscription/qwen-authenticated`
|Grupo `system:authenticated`; rate limits 500/30s y 5000/5m sobre `qwen3-06b`.

|`MaaSAuthPolicy/qwen-authenticated-access`
|Autoriza al mismo grupo sobre el mismo model ref.
|===

NOTE: En RHOAI 3.5 *no* hay un campo de “precio por token” / billing en dólares en la subscription.
El control de coste operativo es por *token rate limits*. El dashboard *Usage* (Technology Preview, módulo 11) sirve para *showback* / atribución de consumo (export CSV), no para facturación oficial.

== Instalar por terminal

[source,bash]
----
oc apply -f manifests/maas-subscription.yaml
----

== Verificar

[source,bash]
----
printf '%-42s %-12s\n' "RECURSO" "ESTADO"
printf '%-42s %-12s\n' "------------------------------------------" "------------"

oc get maassubscription qwen-authenticated -n models-as-a-service --no-headers 2>/dev/null \
  && printf '%-42s %-12s\n' "MaaSSubscription/qwen-authenticated" "OK" \
  || printf '%-42s %-12s\n' "MaaSSubscription/qwen-authenticated" "PENDIENTE"

oc get maasauthpolicy qwen-authenticated-access -n models-as-a-service --no-headers 2>/dev/null \
  && printf '%-42s %-12s\n' "MaaSAuthPolicy/qwen-authenticated-access" "OK" \
  || printf '%-42s %-12s\n' "MaaSAuthPolicy/qwen-authenticated-access" "PENDIENTE"

phase=$(oc get maasmodelref qwen3-06b -n llm -o jsonpath='{.status.phase}' 2>/dev/null)
[ "$phase" = "Ready" ] && printf '%-42s %-12s\n' "MaaSModelRef/qwen3-06b" "OK" \
  || printf '%-42s %-12s\n' "MaaSModelRef/qwen3-06b" "${phase:-PENDIENTE}"
----

IMPORTANT: El nombre `qwen-authenticated` es el que usa el módulo 10 al pedir la API key de Qwen.
