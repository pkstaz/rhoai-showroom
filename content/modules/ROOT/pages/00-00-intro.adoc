= Introducción

Este workshop instala *OpenShift AI {rhoai-version}* en un cluster vacío y deja un modelo *{qwen-model}* publicado en *Models as a Service* (MaaS), servido con *llm-d* en CPU. Después del vertical slice (módulos 1–11) habilita FinOps, guardrails, registry, AutoML/AutoRAG, Prompt Registry, MCP, AgentOps y el plugin de Skills.

CAUTION: Los módulos *8.2 GPU*, *8.3 modelo externo* y *12–22* están en *WIP* (Work in Progress): aún no se validan en lab y pueden cambiar.

El fake GPU no ejecuta CUDA. Sirve para que el cluster anuncie `nvidia.com/gpu` (perfiles, GPU Booking). La inferencia de Qwen corre en CPU. Guardrails, AutoRAG y AgentOps tienen *ruta CPU* y *ruta GPU* cuando el cluster las tiene.

== Tiempo

* Módulos 1–10 (plataforma + MaaS): *~2 h* rápido / *~4 h* explicativo
* Módulos 0.1 + 11 (mapa Lab→Prd, observabilidad): *+60–90 min*
* Módulos 12–22 *WIP* (EvalHub, gobierno, Gen AI Studio, MCP, agentes, Skills): *+2–3 h* según CPU vs GPU

Los waits largos son el Operator de OpenShift AI, la carga del modelo y (si hay GPU) AutoRAG / un vLLM CUDA detrás de NeMo.

. Vista inicial de observabilidad MaaS (COO / Perses / usage dashboards — xref:11-00-observabilidad.adoc[módulo 11])

*Gen AI Studio → AI asset endpoints* (proyecto `llm`) debe listar: *Models* (Qwen), *MCPs*, *Vector stores* y *Agents*.

Los YAML de `manifests/` se clonan en el Web Terminal **después** de entrar como `admin` (módulo 1).

== Qué necesitas

* Cluster OpenShift *4.20+* (llm-d requiere 4.20). El MCP Lifecycle Operator documentado pide *4.22+*; en 4.20 el lab usa un Deployment de fallback.
* Entras como `kubeadmin` (así arranca el cluster)
* Después del Web Terminal, usuario `admin` con `cluster-admin`: OpenShift AI no acepta `kubeadmin` en el dashboard
* Storage class por defecto
* Helm 3 y `oc` (el Web Terminal cubre `oc`)
* Salida a `registry.redhat.io`, `ghcr.io`, `huggingface.co`, `quay.io`

== Regla del lab

En cada módulo: *comando / `oc apply` primero*. Los manifiestos viven en `manifests/` (un directorio por tema). La UI es *verificación* al final, no el camino de instalación.

No instales OpenShift Serverless / Service Mesh *2*. Este lab usa Gateway API; el Ingress Operator instala solo Service Mesh *3* al crear el `GatewayClass`. GPU (módulo 5): single-node con GPU → solo NVIDIA; single-node CPU → solo Fake; nodos GPU+CPU separados → puedes ambos (Fake nunca en el nodo con GPU real).
