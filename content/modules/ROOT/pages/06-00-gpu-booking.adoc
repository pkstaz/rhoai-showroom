= GPU Booking Plugin

Plugin de consola para reservar GPUs. Descubre capacidad desde `nvidia.com/gpu`. Requiere Kueue (xref:03-00-operators.adoc[Prerrequisitos → Operadores base]).

Repo: https://github.com/rhai-code/gpu-booking-app-plugin

== Instalar

[source,bash]
----
git clone https://github.com/rhai-code/gpu-booking-app-plugin.git
cd gpu-booking-app-plugin

helm upgrade -i gpu-booking-plugin chart/ \
  -n gpu-booking-app-plugin \
  --create-namespace \
  --no-hooks

oc patch consoles.operator.openshift.io cluster --type=json \
  -p '[{"op":"add","path":"/spec/plugins/-","value":"gpu-booking-plugin"}]'
----

El Job post-install del chart usa `registry.redhat.io/openshift4/ose-cli:latest` y suele quedar en ImagePullBackOff. `--no-hooks` instala el plugin; el `oc patch` de arriba habilita la consola. Si `gpu-booking-plugin` *ya* está en `.spec.plugins`, el patch con `add` falla por duplicado: omítelo.

Si un `helm upgrade` anterior se quedó colgado esperando el Job, desinstala con `--no-hooks` y vuelve a instalar.

== Verificar

[source,bash]
----
oc get pods -n gpu-booking-app-plugin
oc get consoleplugin gpu-booking-plugin
----

Hard refresh de la consola OpenShift. En perspectiva Administrator aparece *GPU Booking*.

Abre el calendario, dispara *Discover*, y confirma que aparece al menos una GPU (producto, memoria y, si aplica, slices MIG).
El nombre exacto depende de tu cluster: GPU real (p. ej. A100, H100, H200, L40S…) o Fake GPU (`NVIDIA-H200-141GB-HBM3e` con MIG `1g.18gb` / `2g.35gb` / `3g.71gb` si instalaste el módulo Fake).
